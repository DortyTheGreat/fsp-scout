# ФСП Скаут

Платформа подбора ИТ-специалистов с обратной механикой. Кандидат проходит адаптивный тест и получает
подтверждённую категорию (специализация × грейд). Работодатель описывает потребность, выбирает категорию
и сам приглашает конкретного человека, сразу указывая зарплатную вилку и способ связи; до ответа кандидат
может задать вопрос, не раскрывая контакты. Достижения участника Федерации спортивного программирования (ФСП)
подтверждаются подписью реестра и поднимают кандидата в выдаче - тем сильнее, чем сильнее результат и чем
точнее он подтверждает навыки конкретного запроса.

Спецтрек ФСП, ЛЦТ 2026. Команда «veni vidi vivii».

**Что изменили после промежуточной экспертизы** - в [CHANGES.md](CHANGES.md): ФСП под запрос работодателя,
вилка и вопросы до раскрытия контактов, решения у порога грейда, места работы из PDF.

## Что внутри

| Каталог | Что это |
|---|---|
| `backend/` | API на FastAPI: тестирование (IRT + адаптивный тест), подбор, приглашения, вакансии, интеграция с ФСП, LLM-слой |
| `frontend/` | Веб-приложение на Next.js (кабинеты кандидата, работодателя, администратора) |
| `fsp-mock/` | Мок ФСП: ФСП ID (OIDC с URL-схемой Keycloak) и реестр достижений с подписью |
| `validation/` | Процедура валидации: симуляции тестирования и подбора, оценка разбора резюме |
| `docs/` | Сопроводительная документация |

## Быстрый старт (Docker)

1. Запустите **Docker Desktop** и дождитесь в его окне статуса «Engine running». 
2. В папке проекта:

```bash
docker compose up --build
```

Файл `.env` необязателен: без него используются значения по умолчанию из `.env.example`.

- Приложение: http://localhost:3000
- Документация API (Swagger): http://localhost:3000/api/docs
- Мок ФСП ID: http://localhost:8001

При первом запуске создаются схема БД (Alembic) и демо-данные: 300 синтетических кандидатов,
которые прошли тот же адаптивный тест, что и живые пользователи. Это занимает 1–2 минуты.

### Демо-аккаунты (пароль `demo12345`)

| Email | Роль |
|---|---|
| `candidate@demo.ru` | Кандидат без категории: можно пройти опрос и тест с нуля |
| `senior@demo.ru` | Senior-бэкендер с достижениями ФСП, приглашениями и откликом |
| `employer@demo.ru` | Работодатель с подборками, вакансиями и заданиями |
| `admin@demo.ru` | Банк заданий, калибровка, модель ранжирования |

Регистрация нового пользователя требует подтверждения почты. В демо-режиме (`DEMO_MODE=true`) письмо
показывается прямо на экране «Подтвердите почту», в боевом режиме уходит через SMTP.

Вход через ФСП ID (мок): любой `FSP-000001`…`FSP-000400`, пароль `demo`. `FSP-000777` — участник с
призовыми местами, `FSP-000778` — участник без истории соревнований.

## Запуск без Docker

Нужны Python 3.10+ и Node.js 20+. Используется SQLite, PostgreSQL и Docker не нужны.

- **Windows:** Запустить - `run-local.bat` в корне проекта. Скрипт сам найдёт Python и Node.js
  (или подскажет, что установить), поставит зависимости, сгенерирует демо-данные, запустит сервисы и откроет
  браузер. Остановить - `stop-local.bat`. Логи - в папке `.logs`.
- **Linux/macOS:** `./scripts/dev.sh`.

## LLM

По умолчанию `LLM_PROVIDER=none`: всё работает на правилах. LLM необязательна и подключается только
локально, через любой OpenAI-совместимый сервер. Данные не уходят за пределы локального сервера.

- llama.cpp: `llama-server -m model.gguf --port 8080`, затем `LLM_PROVIDER=openai`,
  `LLM_BASE_URL=http://127.0.0.1:8080/v1`, `LLM_MODEL=<имя из /v1/models>`.
- Ollama в Docker: `docker compose --profile llm up -d && docker compose exec ollama ollama pull qwen2.5:3b`,
  в `.env` - `LLM_PROVIDER=openai`.

При локальном запуске без Docker переменные кладутся в `backend/.env`.

**Сравнение правил и модели** на отложенном наборе текстов (резюме, потребности, ответы на задания):
`compare-llm.bat` на Windows или `python validation/llm_compare.py` - при запущенном `llama-server`.
Проверено на Gemma 4 E4B (Q4_K_M) с GTX 1650: модель точнее в разборе текстов и оценке ответов, но тратит
до минуты на резюме, поэтому уточнение моделью идёт фоном - черновик по правилам появляется сразу.

## Тесты

```bash
cd backend && pip install -r requirements-dev.txt && pytest
```

Сквозной тест повторяет сценарий из ТЗ: регистрация → опрос → тест → категория → потребность
работодателя → подборка → приглашение → принятие → раскрытие контактов, а также отклик на вакансию,
привязку ФСП ID через OIDC, ограничения доступа и кулдаун смены грейда.
